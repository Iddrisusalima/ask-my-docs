PART 2  Input length changes nothing about output length
====================================================================
  chars in |  numbers out
-----------+-------------
         7 |          384
        30 |          384
       196 |          384
Same budget of numbers for 7 characters and 200+. A long document
therefore gets *averaged out* into that same fixed space, blurring the
detail. That is precisely why we split documents into chunks before
embedding them (coming up Wed-Thu).

====================================================================
PART 5  Why this matters
====================================================================
Related sentences scored 0.617 on average.
Unrelated ones scored 0.031.
The model was never told these sentences were about baking. It has
no keyword list. It placed them near each other purely from meaning,
and that ordering is what the rest of this project stands on:
  chunk -> embed -> store -> RETRIEVE BY SIMILARITY -> generate
One caveat to remember: these scores are only comparable to each other.
0.62 is not universally 'quite similar' - it depends on the model. Judge
candidates by their ranking against each other, never by a fixed cutoff.
